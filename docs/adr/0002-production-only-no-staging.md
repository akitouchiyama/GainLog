# 0002. 本番環境のみとし、ステージング・検証環境を設けない

- Status: Accepted
- Date: 2026-08（基本設計フェーズ。2026-08-30 の詳細設計キックオフで再確認）

## Context

通常の Web サービスでは本番前の検証環境（ステージング）を用意するが、GainLog は個人開発・実質 1 ユーザーであり、検証環境を持つことのコスト（別 Worker・別 D1・マイグレーション 2 系統・シークレット 2 系統・CI 分岐）と得られる安全性を比較検討した。

## Decision

環境は本番（production）のみとする。ステージング・検証環境は用意しない。

- ローカル開発は `wrangler dev` により本番相当の Worker + D1（ローカル SQLite）構成で行う。
- 本番反映前の動作確認が必要になった場合は、別環境を新設せず `wrangler versions upload`（デプロイせずプレビュー URL を発行）で対応する。

## Consequences

- 運用対象が 1 系統に限定され、マイグレーション・シークレット管理がシンプルになる。
- 本番でのみ再現する不具合のデバッグ手段が限られる。プレビュー URL とローカル再現でカバーする。
- マイグレーションは後方互換な変更に限定する運用（ADR-0004）が、この判断とセットで重要になる。
- 将来、複数ユーザー対応等で利用規模が拡大する場合は再検討する。
